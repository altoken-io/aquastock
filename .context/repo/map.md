# AquaStock repository map

A Solana dApp built for the Stocklana hackathon (NYC): AquaStock Match Pools. A sponsor funds a match on savers' deposits of a tokenized index stock (SPYx, a Token-2022 mint with issuer controls); the match vests linearly on-chain and the vested part is the saver's. This map is a navigation aid — verify against the actual files before editing, and update it when structure meaningfully changes.

## Match Pools (on `main`, live on devnet)

`docs/PIVOT_PLAN.md` is the spec and carries the status. The Anchor program in `programs/` (interface frozen, see `docs/PROGRAM.md`) is deployed on devnet with a replica mint (dSPYx); addresses are in `docs/SETUP.md` ("The devnet demo"). Its typed IDL is at `packages/types/src/program` (`@aquastock/types/program`); PDA, amount-conversion and Anchor-client helpers are in `apps/dapp/src/lib/solana`; the server API is in `apps/dapp/src/app/api` (see `docs/ROUTES.md`) over `apps/dapp/src/lib/pools` (chain reader, service, store, signed-write verification) `apps/dapp/src/lib/price` (live SPYx/USD from Pyth Hermes behind a server-side `PYTH_API_KEY`, shown as "≈ $" next to amounts; hidden without it), and `apps/dapp/src/lib/faucet` (the devnet/localnet demo faucet: the only server code that signs, from a dedicated wallet in `FAUCET_SECRET_KEY`). The `apps/dapp` product UI and the `apps/web` marketing site are both built for Match Pools.

- `programs/`: Anchor 1.2 workspace (`Anchor.toml`, `Cargo.toml`), kept out of the pnpm workspace. The crate is `programs/programs/match_pools` (8 instructions; tests in `tests/` run on LiteSVM against the mainnet Token-2022 build). Built as SBPF v0 because Anchor 1.2 defaults to v3, which LiteSVM rejects.

## Workspace

- `apps/web`: public marketing site (Next.js, Tailwind with automatic source detection off like `apps/dapp`: its `globals.css` lists `src`, `packages/ui/src` and `packages/animation/src`; `en`/`es` via `next-intl` + `@aquastock/locales`). Routes: `/` (home, "Meeting of Waters": first-visit intro curtain, hero photo of two rivers annotated as the mechanism, sponsor/saver marquee, how it works, leaving early (outcome bars from `modules/app/lib/leave-early.ts`), a globe band (`@aquastock/ui/tw/globe`, routes in `modules/app/lib/globe.ts`), FAQ, closing card; both libs tested with `node --test`; images in `modules/app/assets`), `/privacy`, `/terms` (rendered through `modules/app/components/legal/legal-page.tsx`). No accounts, no KYC — pure marketing/informational site that hands off to `apps/dapp` for wallet-connect. Brand mark/favicon/OG image are rendered as code (`src/lib/brand/mark.ts` + `next/og`), not static files — see `docs/ASSETS.md`.
- `apps/dapp`: the product. **`/` is the operator sign-in page, not a marketing home** (marketing lives only in `apps/web`; see `memory: dapp-home-is-login`). Wallet routes live in the `src/app/[locale]/(wallet)/` route group, whose layout mounts `SolanaProvider` (wallet-adapter with Wallet Standard auto-detection, no per-wallet adapters), so only those pages load web3.js, Anchor and the adapter: `/pools`, `/pools/new` (wizard), `/pools/[address]`, `/my-match`. Feature code is in `src/modules/pools` (`components/`, `hooks/` with React Query, `lib/` pure logic: amounts formatting, deposit preview, create-pool validation, position view, tx error classification; `tx/` instruction builders + sender + the one-transaction-at-a-time hook) and `src/modules/wallet` (connect button, and the test-wallet adapter that `next.config.ts` strips from every build except localnet). Server data is read in `src/lib/pools`; the browser only writes by signing transactions. **The Better Auth operator console** (`src/lib/auth/auth.ts`; sign-in at `/`, `/forgot-password`, `/reset-password`; dashboard at `/dashboard` and `/dashboard/pools`) is admin/operator only, dark-first, read-only over the chain (pool totals, deployment facts including the upgrade authority and the token issuer's powers, recent activity); gated by `src/proxy.ts` (cookie presence) and `requireAdminSession()` per page (the real check). Savers and sponsors never sign in. Old water-funding URLs (`/projects`, `/impact`, `/dashboard/projects`, `/dashboard/milestones`) are permanent redirects in `next.config.ts`. Tailwind here has **automatic source detection off** (`@import 'tailwindcss' source(none)` in `globals.css`) and lists `src` and `packages/ui/src` explicitly: auto-detection walks pnpm symlinks into node_modules and produced corrupted class candidates that broke the dev server and the production build. A package that ships Tailwind classes must be added there. Brand mark/favicon/OG image are rendered as code (`@aquastock/ui/brand/mark` + `next/og`), shared with `apps/web`; see `docs/ASSETS.md`. The dApp's signature visual is `modules/pools/components/match-ring.tsx` (the "Confluence": the sponsor's match and the saver's own deposit closing into one ring, with a bezel of 60 ticks that fills as the match vests). See `docs/ROUTES.md` for the route table.
- `packages/ui`: generic shadcn/Base-UI-style component primitives (`src/default/{button,card,code}.tsx`, `src/tw/{avatar,badge,button,button-link,combobox,date-range-picker,dialog,dropdown-menu,globe,input,menu,select,sheet,tabs,textarea,tooltip}.tsx`; `globe` is the cobe WebGL globe). One AquaStock-specific export: `src/brand/mark.ts` (`@aquastock/ui/brand/mark`), the brand mark's SVG path data shared by both apps' logo/favicon/apple-icon/OG image.
- `packages/config`: shared eslint (`eslint/{base,next,react-internal}.js`), typescript (`typescript/{base,nextjs,react-library}.json`), and tailwind (`tailwind/preset.cjs`) presets. Generic, consumed by every app/package.
- `packages/animation`: generic motion/gsap/ogl effect components (marquee, blur, count-up, curved-loop, dot-pattern, text-reveal, etc. under `src/motion/components`). No AquaStock-specific compositions.
- `packages/locales`: i18n content + loader. `src/index.ts` exports `getLocale()`/`locales`/`SupportedLocale`; `src/en.ts` / `src/es.ts` assemble the full per-locale message object from `src/content/{en,es}/*.json`. Current namespaces: `admin` (operator console), `common`, `cookies`, `create`, `deposit`, `earlyAccessCta`, `errors`, `faq`, `faucet`, `footer`, `hero`, `howItWorks`, `importantNotice`, `legal`, `metadata`, `myMatch`, `navbar`, `newsletter`, `pools`, `position`, `privacy`, `sponsor`, `terms`, `tx`, `useCases`, `validation`, `wallet`. Both apps' `src/lib/i18n/types/global.d.ts` type-augments `IntlMessages` from this package, so `t('some.key')` calls are compile-time checked against these JSON files — a missing key is a `tsc` error, not just a runtime one.
- `packages/types`: shared transport types. `src/pool.ts` is the API's DTOs (`PoolDto`, `PositionDto`, `PoolActivityDto`, `DeploymentDto`, `IssuerPowersDto`, ...; amounts are decimal strings of raw units), and `src/program` is the program's typed IDL (`@aquastock/types/program`). Resolved with Bundler module resolution and listed in `transpilePackages`.
- `packages/db-prisma`: PostgreSQL Prisma schema for off-chain data only (see `docs/DATABASE.md`): `Pool` (descriptive metadata for an on-chain pool) and `PoolActivity` (transactions the server verified from the chain), plus the Better Auth tables for the `apps/dapp` admin login (hand-kept in sync with `npx @better-auth/cli generate` output, since this package's Prisma 7 driver-adapter setup trips up the CLI's own schema writer). The old `Project`/`Position`/`Milestone`/`Impact` tables were dropped by a guarded migration. `lib/prisma.ts` exports a `PrismaClient` singleton on the `@prisma/adapter-pg` driver adapter, plus `createPrismaClient(connectionString)`. `scripts/migrate-deploy-prod.mjs` and `scripts/create-admin-user.mjs` are prod-DB tooling meant to be run by a human holding `.env.prod`, not by an agent (see CLAUDE.md's env-file rule).

## What does NOT exist yet (do not assume otherwise)

- **No mainnet deployment.** The team chose devnet only; deploys are run by a human (`pnpm program:keygen`, `pnpm program:deploy`).
- **No `apps/api`.** There is no separate backend service: `apps/dapp` serves its own off-chain data through Next.js route handlers.
- **No `apps/mobile`.** Web-only (`apps/web` + `apps/dapp`).
- **No saver or sponsor accounts.** No KYC, no login for them: everything is wallet-connect. (The operator login is a separate, staff-only concern.)

## Commands

- `pnpm dev:stack`: one command for a complete local demo with no keys of yours: disposable Postgres (port 5434), a local validator with the program and the mainnet Token-2022 build, a demo replica mint and pool, a throwaway browser test wallet, and the dapp on :3003 (Turbopack; `--webpack` opts out). Ctrl+C stops it all. Use this, not `pnpm dev`, to click through the product.
- `pnpm test:e2e`: the Playwright specs (`apps/dapp/e2e`: golden path, the sponsor's reclaim after a pool closes, the demo faucet, the timed demo dry run) on desktop and mobile viewports, against the local stack (it starts `pnpm dev:stack` itself). `pnpm test:e2e demo-dry-run` times the demo script's beats. Not part of `pnpm check`. `DEV_STACK_TEST_WALLET=0 pnpm dev:stack` runs the stack with no test wallet, to see the app as a visitor without one (the phone connect flow).
- `pnpm dev`: runs `apps/web` (port 3000) and `apps/dapp` (port 3003, webpack) together.
- `pnpm dev:web` / `pnpm dev:dapp`: run one app only.
- `pnpm lint`, `pnpm check-types`, `pnpm test`, `pnpm format` (writes) / `pnpm format:check` (verifies): workspace quality checks via Turborepo.
- `pnpm check`: full validation gate — `format` then `turbo run lint check-types test build`. Run before every commit/PR. `workflows/check.yml` runs the same (minus the Next.js builds, which need real env and are built by Vercel) on every push/PR against a throwaway Postgres service container.
- `pnpm program:test`: builds the program (SBPF v0) and runs the unit, property and LiteSVM tests. `pnpm program:build`, `pnpm program:idl` (regenerates `packages/types/src/program`), `pnpm program:fixtures` (fetches the mainnet Token-2022 build the tests use).
- `pnpm program:smoke`: boots a local validator and runs the whole product flow through the typed client (about a minute). `pnpm program:localnet` runs the validator in the foreground.
- `pnpm program:keygen <devnet|mainnet>` then `pnpm program:deploy <devnet|mainnet>`: run by a human with their own wallet; never by an agent. `pnpm solana:replica-mint`, `solana:mint-replica` and `solana:init-config` set up the demo mint and the allow-list. `pnpm solana:faucet` creates or tops up the demo faucet wallet; `pnpm solana:demo-pool --api <app url> --name ...` creates a named, funded pool (both in `docs/SETUP.md`).
- `pnpm clean:cache` (`scripts/clean-next-cache.js`): clears every `.next` directory in the workspace. It used to be the fix for the dev-mode "Parsing CSS source code failed" overlay; the cause was Tailwind's automatic source detection (see `apps/dapp` above), now switched off in both apps (`apps/web` since 2026-09-22), so it should not recur.
- `pnpm demo:preflight` (`scripts/solana/preflight.ts`): read-only check of the live deployment before a demo or submission (build vs HEAD, faucet, pool budget and window, database, Pyth price, pages, security headers, public repo); exits 1 on a failure. `--live` adds a real devnet round trip with a throwaway, faucet-funded wallet. Submission copy and checklist: `docs/SUBMISSION.md`.
- `pnpm secrets:scan` (`scripts/scan-secrets.sh`, rules in `.gitleaks.toml`): gitleaks over full git history.
- `docker compose -f docker-compose.dev.yml up -d`: disposable local Postgres only (no Redis) for `packages/db-prisma` — credentials match the local `DATABASE_URL` convention (`postgresql://postgres:postgres@localhost:5432/aquastock`); override `POSTGRES_HOST_PORT` if 5432 is already bound.
- `pnpm --filter @aquastock/db-prisma exec prisma migrate dev` / `prisma studio`: schema migrations / DB browser.
- `pnpm --filter @aquastock/db-prisma create-admin-user -- --email you@x.com --name "Your Name" [--env .env.prod]`: only way to create an `apps/dapp` admin account — there is no public sign-up route.

## Conventions

- Use pnpm and Turborepo; keep feature code in its owning app until it has a stable shared contract.
- Public and dApp pages are locale-aware under `[locale]`; keep `en`/`es` namespace parity in `packages/locales` — `apps/dapp/src/lib/i18n/locale-parity.test.ts` enforces this (same namespace files, identical key paths, in both locales) and fails CI on drift.
- Prisma schema/migrations (`packages/db-prisma`) own the off-chain database; once the Anchor program exists, it is the source of truth for on-chain state, and the Prisma rows are a cache/display layer keyed by `onchainAddress`.
- Docs in `/docs` describe product direction, architecture, and development rules — see each doc's own header for current relevance (some still reference the prior project this repo was built from and are being rewritten separately).
- `apps/web/PRODUCT.md`, `apps/dapp/PRODUCT.md`, `apps/dapp/DESIGN.md` are the current brand/product/design references for UI work (see CLAUDE.md's "UI and styling rules").
